# 解説動画キット ── Claude Code 引き継ぎ用

トランジスタからOSまでの学習動画(全36回)を作るための土台。
第1回・第2回・第10回・第17回は完成済みで、参照実装として入っている。

## 構成

```
common.py                  共通モジュール(色・フォント・シーン管理・レンダ)
ep_template.py             ひな形。これをコピーして中身を差し替える
check.py                   レンダ結果から指定秒のフレームをPNGに切り出す
episode-specs.md           全36回の「画面で何を動かすか」の仕様
ep01_denki.py              完成品:電気とは何か
ep02_kairo.py              完成品:回路の読み方
ep10_mosfet_narrated.py    完成品:MOSFET(音声付きの実装例)
ep17_and_or.py             完成品:直列と並列
narrate_optional.py        音声合成(採用していない。下記参照)
```

## 環境

```bash
# 必要なもの
ffmpeg
python3 -m pip install matplotlib numpy scipy
fc-list :lang=ja        # 日本語フォントの確認
```

日本語フォントは `common.py` の `_NOTO` でパス直指定している。
環境が違えば `fc-list :lang=ja` の結果に差し替える。
`.ttc` はフォント集合だが、`FontProperties(fname=...)` で index 0 が
Noto Sans CJK JP になるのでそのまま使える。

## 作業手順

1話ずつ。まとめて作らない。

```bash
cp ep_template.py ep03_condenser.py
# episode-specs.md の該当回を読んで実装
python3 ep03_condenser.py
python3 check.py out/ep03_condenser.mp4 3 11 20 28 36
# ← 切り出したPNGを必ず目で見る。ここを飛ばすと崩れたまま量産される
```

## 守ること

**毎回フレームを目で見る。** ffmpeg が正常終了しても、ラベルが重なる・
画面外に出る・要素が別の要素の上に乗る、は普通に起きる。実際に完成済みの
4本すべてで、1回目のレンダは何かが重なっていた。exit 0 は「壊れていない」
ことしか意味しない。

**高さの帯を守る**(座標系は 160 x 90)。

| y | 用途 |
|---|---|
| 4〜10 | 字幕。`Scenes.caption()` が置く。触らない |
| 18〜28 | 数式・数値・結論の一行 |
| 35〜70 | 装置本体 |
| 70〜85 | 装置の補助ラベル、矢印 |

守らないと字幕と本体がぶつかる。これが崩れの最大の原因。

**`draw(frame)` は状態を持たない。** その時刻の画を毎回全部描き直す。
累積が必要なもの(電子のドリフト位置など)は、事前に全フレーム分の配列を
計算してから引く。`ep01_denki.py` の `DRIFT` がその例。

**色を増やさない。** `common.py` の定数だけを使う。1話ごとに新色を足すと
全体でバラける。

**`if __name__ == "__main__":` を必ず付ける。** 付けないと、フレーム確認の
ために import しただけで本番レンダが走る。

**1本 60〜80秒、20fps、1280x720。** スマホで見るので字幕は21pt以上。
1本のレンダに1〜2分かかる。`blit=True` は使わない(毎フレーム全消しのため)。

## 音声について

`narrate_optional.py` は pyopenjtalk による音声合成で、動作はする
(`ep10_mosfet_narrated.py` が実装例)。ただし抑揚がほぼ無い棒読みで、
品質が実用に届かないため**採用していない**。字幕のみで進める。

やるなら、まず全話のナレーション原稿の長さを測り、その尺に合わせて
シーン境界を決める。逆順にすると必ず音が映像からはみ出す。
